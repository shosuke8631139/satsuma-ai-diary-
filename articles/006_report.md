## チャットAIだけでなく、バイブコーディングを使う理由

発信にAIを使い始めたのは、ChatGPTとGeminiでチャットしながらキャプションなどを作っていた頃からです。
話しながら言葉を整えてもらえるので、最初は「これで十分じゃないか」と思っていました。ていうか、全然普通に使えます。

でも使い込んでいくと、だんだんと気になることが出てきました。話せば話すほど、前に言った話を忘れていく。
「あれ、さっきと言っていることが違う」「なんか自分のことが全然わかってくれていない感じになってきた」

AIが迷子になる理由はシンプルで、AIは**「記憶力はいいけど、集中力がすぐ切れる天才」**だからです。

ChatGPTのようなLLMは「それっぽい答え」を返してくるのが得意です。でも話せば話すほどコンテキストが積み重なると、だんだん答えがずれてくる。覚えてるようで、実際は覚えていない。

一言で例えるなら、**「入口と出口しか明るくない、長いトンネル」**のような状態です。

- **入口（最初）**: 最初に決めた「ルール」や「目的」には光が届いているので、よく見えている
- **出口（最後）**: 今さっき言われた「直近の話題」も目の前にあるのでハッキリ見える
- **真ん中**: 話が長くなればなるほど暗くなり、AIの目に映らなくなってしまう

専門用語では「Lost in the Middle（真ん中で迷子になる）」と言いますが、まさに**「端っこにしかライトが当たっていない」**のが今のAIの特徴です。

## バイブコーディングに変わって、ファイルに残すようになった

Claude CodeとCursor、それからAntigravityを使い始めて、明らかに違うと気づいたことがあります。

**考えたことが、フォルダとファイルに残っていく。**

ちょっとした「あ、これは違うな」という気づきも、ファイルに残ればあとから拾える。チャットだと、その瞬間に流れていく。

フォルダは最初から完成に設計しているわけではありません。これまで溜めてきた内容やテキスト、AIとのやりとり──全部含めてインプットを重ねていて、その中から少しずつ整ってきた感じです。

---

## AIは確信する。でも「内の目」が要る

正直に言うと、AIに頼りすぎることへの不安が、ずっとあります。

確認の仕方としては、いろいろなAIの意見を聞くようにしています。最後にどうするかは、自分で決めています。

不思議なのは、AIから質問を投げかけてもらって、その質問に自分が答えようとすると、「次に考えること」「次の問い」が自然と見えてくる瞬間があること。

**調べているのはAI、でもそこから出てくるのは自分の中にあったものです。**

いい先生が「なぜそう思うの？」と聞いてきた瞬間に、自分でも気づいていなかった答えが出てくる──あの感覚に近い気がしています。それがAIとうまく付き合えていると感じる瞬間です。

AIは確信してくれます。でもその方向が正しいかどうかは、自分の「内の目」で確かめていくことが大事。ファイルへの蓄積と自分の意見、その両方がセットになって初めて機能します。

## 具体例：古家の学びで、メンター的に使った

たとえば古家の学びをしているとき、自分一人では思わない続け方や副業の考え方、どのペースで進めると安心かみたいな話が、AIとの会話の中で自然と出てきました。

「知らないとつい大きな判断をしてしまいがちなこと」を、一緒に整理できた感じです。

調べれば調べるほど、次の問いが生まれる。その不思議さが、学びとAIとの関係の中にあります。

---

## 6月、古家が手に入ったら：AIと一緒に一つずつ確認する

そこから何をすべきか。最初に全部わかっているわけではないので、AIに質問を受けながら一つずつ確認していくつもりです。

たとえば「雨漏りを見つけたら最初にすること」「古い電気系統はどこから確認するか」──こういうことを、現場に着く前に一つずつ頭に入れておきたい。

知らずに踏み込むより、知ってから動く方が、安全にも気持ちにも余裕が生まれます。

どれを先にやるか・どの順で向き合うかの優先順位は、自分の目で見て決めます。そのときの基準として、**安全を最優先**に置いています。写真や動画には収まらない、現場でしか感じられないものがある。その感覚こそを、判断の軸に置いておきたいと思っています。

## 音声との組み合わせで、すべてが変わった

テキストだけではないのが、このワークフローです。

**AquaVoice（声入力）で話す → テキストに変換 → Claude Codeに渡す → VS CodeでAIと整える → HTMLでプレビュー → noteにコピペ**

考えた内容をファイルに残すことで、「翌日の続き」に繋げやすくなりました。AIに「前の判断」を蓄積させておくことで、今日の整理が楽になっています。

これは「なぜバイブコーディングを使うのか」という記事なのに、実際にその方法で作られています。同じことをやりながら記事が出てくる、という構造になっています。

---

## 誰でもできる。でも始めたのは「始めることを怖れている人」のため

この仕組み、知っていれば誰でもできると思っています。ただ、知らない人は多い。実際に使ってみないと伝わらないから、発信し続けています。

50万円で買った古家を、少しずつ直しながら、春先に地元に根付く──その過程を発信し続けることが、自分にとってのミッションだと思っています。

「AIに判断を積み重ねさせていく」こと、それがその分身を育てる動力なのかもしれない。そうなったとき、今積み重ねてきた自分のデータや判断が、どんなふうに使われるかはわからない。でも、今のうちから自分の考え方や感じ方を残しておくことには、意味があると思っています。

## 学びの設計図

- **Trigger（きっかけ）**: チャットAIの「真ん中迷子問題」に気づく
- **Source（素材）**: AquaVoiceで話した内容がそのままテキストとして蓄積される
- **Process（処理）**: Claude Code + Cursor でファイルに考えを残しながら整える
- **Output（届け先）**: note記事として発信→「始めることを怖れている人」に届く

## 今日使ったAIツール

- AquaVoice（音声入力・声で話す）
- Claude Code（ファイルへの蓄積・記事整形）
- Cursor / Antigravity（バイブコーディング環境）
- Gemini（リサーチ・Deep Research）
- VS Code（エディター）
