# 薩摩AI修行日誌 Episode #5 | チャットAIだけでなく、Vibe Codingを使う理由

日付: 2026年4月11日（金）

## 今日のテーマ

なぜチャット形式のAIだけでなく、Vibe Codingを使っているのか。
古家との再会は6月の予定。楽しみな時間。

## 最初はChatGPTとGeminiで作っていた

発信にAIを使い始めたのは、ChatGPTとGeminiでチャットしながらキャプションなどを作っていた頃からです。

話しながら言葉を整えてもらえるので、最初は「これで十分じゃないか」と思っていました。

でも使い込んでいくと、気になることが出てきました。

話せば話すほど、前に言った話を忘れていく。

「あれ、さっきと言っていることが違う」「なんか自分のことが全然わかってくれていない感じになってきた」という気づきの積み重ねです。

ChatGPTのようなLLMは、基本的に「それっぽい答え」を返してくるのが得意です。でも、話せば話すほどコンテキストが積み重なっていくと、だんだん答えがずれてくる。覚えてるようで、実際は覚えていない。

たとえるなら、毎回初対面の人に同じ自己紹介をしているような感覚です。「前も言ったよ」が通じない。

## Vibe Codingに変わって、ファイルに残すようになった

Claude CodeとCursor、それからAntigravityを使い始めて、明らかに違うと気づいたことがあります。

考えたことが、フォルダとファイルに残っていく。

チャット形式は話し終わるとリセット。でもVibe Codingだと、気になったこと、「これは正しくない」と思い直したことも、そのままファイルに蓄積されていきます。そこが決定的に違う。

ちょっとした「あ、これは違うな」という気づきも、ファイルに残ればあとから拾える。チャットだと、その瞬間に流れていく。

使えば使うほど文が出てくる。余すことなく残す。その積み重ねが、少しずつ「場所」の感触になっていきます。

フォルダは最初から完成に設計しているわけではない。これまで溜めてきた内容やテキスト、AIとのやりとり──全部含めてインプットを重ねていて、その中から少しずつ整ってきた感じです。

## AIは確信する。でも「内の目」が要る

正直に言うと、AIに頼りすぎることへの不安が、ずっとあります。

確認の仕方としては、いろいろなAIの意見を聞くようにしています。最後にどうするかは、自分で決めています。

ただ──AIに任せることに集中しすぎると、自分の引き出しが出てこなくなる感覚があります。

不思議なのは、AIから質問を投げかけてもらって、その質問に自分が答えようとすると、「次に考えること」「次の問い」が自然と見えてくる瞬間があること。

いい先生が「なぜそう思うの？」と聞いてきた瞬間に、自分でも気づいていなかった答えが出てくる──あの感覚に近い気がしています。

AIは確信してくれます。でもその方向が正しいかどうかは、自分の「内の目」で確かめていくことが大事。

## 学びの設計図

- **Trigger（きっかけ）**: チャットAIのズレに気づく → Vibe Codingへ移行
- **Source（素材）**: AquaVoiceで話した内容がそのままファイルに蓄積される
- **Process（処理）**: Claude Code + Cursor でファイルに考えを残しながら整える
- **Output（届け先）**: note記事として発信 → 「始めることを怖れている人」に届く

## 今日使ったAIツール

- AquaVoice（音声入力・声で話す）
- Claude Code（ファイルへの蓄積・記事整形）
- Cursor / Antigravity（Vibe Coding環境）
- Gemini（リサーチ・Deep Research）
- VS Code（エディター）

## 今日の最大の収穫

「フォルダは設計するものではなく、育てるもの」という感覚が言語化できた。
チャット形式は話すほどズレる。Vibe Codingはファイルに残すから積み重なる。
AIは確信してくれるが、方向が正しいかは「内の目」で確かめる。
この仕組みは、始めることを怖れている人にこそ届けたい。

## 5年後の話

AIの進歩がこのまま続いていくと、積み重ねられたデータが「自分の分身」になっていくんじゃないか。
「AIに判断を積み重ねさせていく」こと、それがその分身を育てる動力なのかもしれない。

今のうちから自分の考え方や感じ方を残しておくことには、意味があると思っています。
