自動報告ツールのしくみ

文章で日報を書くと、自動で「見やすいカード画像」ができて Slack に届くまでの流れです。スクールの月次課題（報告ツール）向けに、画面キャプチャ欄と工夫の説明もこのページにまとめています。

▼ ぜんたいの流れ（上から下へ読む）▼

① 記事を書く パソコンで Markdown（日報の文章）を書きます
↓

インターネット上の「提出ボックス」に送るイメージ

② GitHub に送る 保存して送る（push）と、自動のスイッチが入ります
↓
③ クラウドで自動処理 GitHub Actions が動き、AI が文章を整理 → デザイン用 HTML に入れる → ブラウザの真似をしてカード画像（PNG）を撮ります
↓
④ Slack に届く できあがった画像が、チームのチャンネルに通知されます

報告ツールの画面（スクリーンショット）

提出要件①：実際のツール画面の画像を下に貼ります。

画像が表示されないとき： この HTML と同じ docs フォルダに、スクショ画像を submission-screenshot.png という名前で保存して GitHub に push してください。ファイル名を変える場合は、このページの img の src を編集します。

工夫したポイント（提出要件②）

4つのパーツの決め方・デザイン・課題と解決を、ツールの設計に沿って整理しています。言い回しはご自身の体験に合わせて書き換えて問題ありません。

4つのパーツ（Trigger / Source / Process / Output）の決め方

Trigger（きっかけ）

articles/ 配下の記事を書いて GitHub に push した瞬間にだけ処理が走るようにした。手動ボタンや別サービスに依存せず、「日報を届けたら報告が完了する」一連の流れに寄せた。

Source（素材）

素材はプレーンな Markdown の記事本文に限定。フォーム入力ではなく「自分の言葉で書いた長文」をそのままソースにすることで、発信のハードルを下げつつ中身の厚みは保てるようにした。

Process（処理）

クラウド上で Gemini が構造化データを抽出 → Jinja2 で HTML テンプレートへ注入 → Playwright がカード部分を PNG で撮影、という三段に分けた。人間がレイアウト調整しなくても毎回同じ体裁になる。

Output（届け先）

チームの Slack チャンネルへ Incoming Webhook で通知。テキストの要約ブロックに加え、カード画像も見せられるようにして、スクロールしなくても「今日の一行」が伝わるようにした。

デザインの工夫

  • 報告カード：ダークグリーン×エメラルド系で統一し、進捗バーや4ステップ（きっかけ→素材→処理→アウトプット）が一目で追えるカード型 UI にした。
  • キャラクター：はるくん・さくらじまおのセリフをテンプレートと AI 生成で両立させ、読み物としての温度感と「報告」としての型を両立させた。
  • この図解ページ：提出先が URL 一つで済むよう、流れ図・キャプチャ・説明文を単一 HTML に集約し、スマホでも読める幅（最大 720px）にした。

ぶつかった課題と解決

  • 課題：Slack の Block Kit では、画像ブロックにインターネット上の公開 URLが必要で、Actions の実行環境だけに保存した PNG をそのままは貼れない。解決：生成 PNG を一時的に外部ホストにアップロードし、返ってきた HTTPS URL を Slack に渡すようにした。
  • 課題：記事ごとに項目がバラバラになりがち。解決：Gemini に JSON スキーマに近い指示を固定し、毎回同じキー（進捗・4サイクル・ツール一覧など）でテンプレへ流し込めるようにした。
  • 課題：CI 上でブラウザ相当の描画が必要。解決：Playwright の Chromium を Actions でインストールし、テンプレートをファイルとして開いてから要素単位でスクリーンショットする。

用語をやさしく言い換えると

  1. GitHub … プログラムと文章を置いておく「ネット上の作業場」
  2. GitHub Actions … 「送ったら自動でやることリスト」を動かす仕組み
  3. Slack … チームで話すチャット（届け先）
このURLを出すには： GitHub のリポジトリで Pages をオンにして、公開フォルダを /docs にすると、ブラウザ用の固定URLがもらえます。（リポジトリの Settings → Pages）
